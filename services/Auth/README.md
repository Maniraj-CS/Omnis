# Auth Service

An Express and TypeScript authentication service. It stores users in PostgreSQL, hashes passwords with Argon2, and stores login sessions in Redis. Successful registration and login return the user and set an HTTP-only `session_id` cookie.

## Requirements

- Node.js and npm
- Docker Compose
- A PostgreSQL database
- A Redis server

The included `docker-compose.yml` starts local PostgreSQL and Redis containers. PostgreSQL is configured with database `app_db`, user `app_user`, and password `local_password`; the local connection strings in `src/config/db.ts` and `src/config/redis.ts` use those values.

## Setup

From this directory (`services/Auth`), install dependencies and create a `.env` file with at least a port:

```env
PORT=3001
NODE_ENV=development
CORS_ORIGINS=http://localhost:5173
```

`CORS_ORIGINS` is a comma-separated list of browser origins allowed by the current CORS configuration. Include the exact origin used by your frontend, including its scheme and port.

Start the service:

```bash
npm install
npm run dev
```

The dev script starts the Docker Compose services and runs TypeScript compilation in watch mode alongside Nodemon. The server connects to Redis and PostgreSQL during startup.

### Database table

The service expects a PostgreSQL table named `users` with these columns:

| Column | Type / behavior |
| --- | --- |
| `id` | UUID primary key, generated by PostgreSQL |
| `name` | `VARCHAR(100)`, required |
| `email` | `VARCHAR(255)`, required and unique |
| `password_hash` | `TEXT`, required |
| `system_user` | Boolean, defaults to `FALSE` |
| `created_at` | Timestamp, defaults to the current time |

The current dev script does **not** create this table, and this service folder does not currently include a schema file. Create the table in `app_db` before calling register. The `id` default uses `gen_random_uuid()`; the PostgreSQL instance must provide that function.

## API

All routes are prefixed with `/api/v1/auth` and accept JSON request bodies.

### Register

`POST /api/v1/auth/register`

```json
{
  "name": "Ada Lovelace",
  "email": "ada@example.com",
  "password": "a-password"
}
```

On success, returns `201`, sets the session cookie, and returns the created user. Invalid input returns `400`; an existing email returns `409`.

### Login

`POST /api/v1/auth/login`

```json
{
  "email": "ada@example.com",
  "password": "a-password"
}
```

On success, returns `200` and sets the session cookie. Invalid input returns `400`; incorrect credentials return `401`.

### Logout

`GET /api/v1/auth/logout`

Requires the `session_id` cookie. It deletes the Redis session and clears the cookie.

Send and retain cookies from the client when using the API. For example, browser clients making cross-origin requests need to send credentials; the frontend origin must also be listed in `CORS_ORIGINS`.

## Sessions and configuration

- Redis session keys use the `session:` prefix and have a five-minute inactivity lifetime. Authenticated requests refresh the Redis expiry and cookie expiry.
- `PORT` selects the HTTP port. Set it in `.env`; the server does not provide a default port.
- In development, PostgreSQL and Redis URLs are fixed in their respective config files.
- In production (`NODE_ENV=production`), PostgreSQL uses `DATABASE_URL` and Redis uses `REDIS_URI`.
- The session cookie is `httpOnly`, uses `sameSite: lax`, and is marked `secure` in production.

## Other commands

```bash
npm run build
npm start
```

`npm start` runs the compiled server from `dist`; build first with `npm run build`.

## Build the container image

From this directory, build the production image:

```bash
docker build -t omnis-auth .
```

Run it with the production database and Redis URLs supplied as environment variables:

```bash
docker run --rm --name omnis-auth \
  -p 3001:3001 \
  -e PORT=3001 \
  -e NODE_ENV=production \
  -e DATABASE_URL='postgresql://user:password@database-host:5432/app_db' \
  -e REDIS_URI='redis://redis-host:6379' \
  -e CORS_ORIGINS='http://localhost:5173' \
  omnis-auth
```

The database and Redis hostnames must be reachable from the container. If running those dependencies in Docker Compose, put the Auth container on the same Compose network and use the Compose service names as their hosts. The table described above must already exist; the image does not create or migrate database tables.
